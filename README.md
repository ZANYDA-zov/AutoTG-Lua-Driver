## 🚀 Why AutoTG?

Most automation tools force you into rigid, click‑and‑record workflows. AutoTG flips that script. Here, you don't just record – you **compose**. Whether you're verifying a game's UI after a patch, stress‑testing a legacy desktop application, or building a regression suite that runs while you sleep, AutoTG gives you the keys.

Built with a lightweight Lua runtime and a native input/screen capture layer, AutoTG bridges the gap between "it works on my machine" and "it works everywhere, every time."

## ⚙️ How It Works

AutoTG operates on a simple three‑layer model:

1. **Perception** – Captures the screen, reads pixels, and optionally runs OCR or template matching.
2. **Decision** – Your Lua script interprets the captured data using conditions, loops, and state machines.
3. **Action** – Simulates input events (clicks, keys, swipes) back into the application.

Because everything is script‑driven, you can version‑control your tests, diff changes, and review automation logic like any other code.
